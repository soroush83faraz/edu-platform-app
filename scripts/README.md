# scripts
Operational CLIs run with `tsx` locally: `migrate` (also as pg-only `migrate.js` inside the image), `seed` (its catalog half also as the generated pg-only `seed-catalog.js`), later `import`, `build-template`. They may import `src/db/*` and create their OWN pool as `app_owner` (`MIGRATION_DATABASE_URL`).

- `pnpm seed` → `seed.ts --catalog`: permissions + system roles + work item types/statuses + notification types (idempotent, authoritative). Run after every migrate locally. The data and the pg-only writer live in `catalog.ts`; `build-seed-catalog.ts` (run by `pnpm build`, also `pnpm build:seed-catalog`) compiles `seed-catalog.ts` + `catalog.ts` + `src/modules/iam/permissions.ts` into the single-file, gitignored `seed-catalog.js` (CommonJS, `pg` only — the build refuses any other bare import) that the `seed` service of `deploy/compose.yml` runs after `migrate` on every deploy (`node scripts/seed-catalog.js`; `--test` → `MIGRATION_DATABASE_URL_TEST`). No `SEED_ALLOW` needed: catalog rows only.
- `pnpm seed:demo` → `seed.ts --catalog --demo` (requires `SEED_DEMO=1`; `SEED_DEMO_PASSWORD`, `SEED_DEMO_NO_FORCE=1` optional). Deterministic ids/phones; re-running resets the demo passwords.
- `pnpm seed:pilot` → `seed-pilot.ts`: the PILOT dataset — three separate organizations/tenants (`allameh` → school `ALK`, `farzanegan` → `FRZ`, `helli` → `HL4`), each with year ۱۴۰۵-۱۴۰۶ + two terms, grades, 9–10 subjects, 7–8 classes, org admin + principal + vice + 10 teachers, 25 students per class (~550 total; 60 % log in by phone, the rest by `<code>-<number>` username), offerings with main teachers and a living کارتابل (2–4 tasks per teacher with spread due dates, 30–50 % of each class commenting «انجام دادم» and marking done, staff todos, principal→teacher tasks). Runs the catalog seed first; everything goes THROUGH the real services with the acting person's real ctx (`listValidAssignments`). Deterministic ids (`sha256("edu-pilot:"+key)`), phones `+9893510xxxxx` / `+9893520xxxxx` / `+9893530xxxxx`; idempotent — a re-run inserts nothing (`tests/int/seed-pilot.test.ts`). One shared password `PILOT_PASSWORD` (default `Pilot-1405-pass`, no forced change); the accounts sheet goes to `backups/pilot-accounts.md` (gitignored). `PILOT_SCALE=0.2` shrinks it for tests. ~3 min for a fresh run on a laptop (≈ 600 argon2 hashes + ~30k rows).
- `pnpm seed:demo-extras` → `seed-demo-extras.ts` (plan: `demo-extras-plan.ts`): demo content for EVERY role of the three pilot organizations on top of `seed:pilot` (run that first; slugs missing from the database are skipped, other organizations are never touched). Per organization: 4 «تسک» from the organization admin to the principal/vice (one overdue, one done by the principal, one extended, one closed with «اتمام»), 4 from the principal and 2 from the vice principal to دبیران (some done, one extended, one closed), 2 personal notes each for admin/principal/vice, 1–2 own «تسک» for the first four students (`student-0` = phone `0935X001000`), and 3 «تکلیف» of the first دبیر (`0935X000011`: partly done by the class → n/m, one «اتمام», one «تمدید»). Deadlines are relative to the Tehran day of the run (overdue 1–3 days, today 23:30, this week, later, none) — run it on or just before the demo day. Everything goes through `createWorkItem` / `changeStatus` / `updateWorkItem` / `markInboxRead` / notif `markRead` with each person's real ctx, so audit rows (`request_id = seed-demo-extras`), inbox entries and notifications follow the current policy (an assignee's «انجام شد» notifies nobody; the organization admin's bell therefore stays empty). Only the «… جدید» notification of an item its assignee finished or opened is marked read; the rest stay unread. It also renames pilot notifications titled «کار جدید: …» to the creator's current word. Idempotent: each item carries `work_item.idempotency_key = demoItemKey(org, slug)` and is looked up by (creator, key); done marks, «اتمام» and «تمدید» (audit row) are skipped when present — a second run writes nothing (`tests/int/seed-demo-extras.test.ts`). `--prune-legacy-status` (opt-in, deletes rows) also removes the pilot organizations' `work_item.status_changed` notifications written by an ASSIGNEE's «انجام شد» under the pre-round-7 policy («… را انجام‌شده کرد (n/m)» — ~20 unread per دبیر in a pilot seeded before round 7). Runs as `app_owner` (`MIGRATION_DATABASE_URL`); refuses `NODE_ENV=production` unless `SEED_ALLOW=1`, like `seed:pilot`.
- `build-seed-bundles.ts` (`pnpm tsx scripts/build-seed-bundles.ts`; NOT part of `pnpm build`) bundles `seed-pilot.ts` and `seed-demo-extras.ts` with esbuild (tsx's own copy) into self-contained ESM files, `build/seed-bundles/{seed-pilot,seed-demo-extras}.mjs` (gitignored), for loading the pilot on a server with no npm. External = what the standalone image ships (`pg`, `@node-rs/argon2`, `pino`, `next`); drizzle-orm, zod, uuid and date-fns-jalali are inlined. They resolve those packages from `/app/node_modules`, so mount them UNDER `/app`: `cd /srv/school && PILOT_PASSWORD="$(cat pilot-password.txt)" docker compose run --rm --no-deps -T -v /srv/school/tools:/app/tools:ro -v /srv/school/pilot-out:/out -e SEED_ALLOW=1 -e PILOT_PASSWORD -e PILOT_ACCOUNTS_DIR=/out seed node /app/tools/seed-pilot.mjs` (then `seed-demo-extras.mjs`). `PILOT_ACCOUNTS_DIR` moves the accounts sheet out of the read-only `/app`; a sheet that cannot be written is a warning, not a failed seed.
- Production refuses `seed.ts` (demo), `seed-pilot.ts` and `seed-demo-extras.ts` unless `SEED_ALLOW=1`; the catalog-only `seed-catalog.js` runs in production by design (see deploy/README.md «سید کاتالوگ»).
- `pnpm smoke:prod` → `smoke-prod.ts`: black-box end-to-end probe of a RUNNING deployment over HTTP only (`BASE_URL`, `SMOKE_IDENTIFIER`, `SMOKE_PASSWORD`): health → real login form → inbox summary → create todo → done → logout → protected route redirects. Run after every deploy (docs/ops/runbook.md).
- `pnpm sessions:revoke --user <login> | --org <slug> --yes | --all --yes` → `revoke-sessions.ts`: revokes live sessions through `withoutTenant`/`withTenant` + `revokeAllForUser` (incident lever, docs/ops/incident.md). Runs as `app_rw` (`DATABASE_URL`).
