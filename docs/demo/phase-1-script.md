# سناریوی دموی فاز ۱ — ۱۲ دقیقه

هدف: مدیر مدرسه در ۱۲ دقیقه ببیند «امروز چه کنم» برای سه نقش جواب دارد، خودش یک دانش‌آموز بسازد، و مطمئن شود داده‌ها امن و پشتیبان‌گیری‌شده‌اند. بندهای پذیرش (`docs/acceptance/phase-1.md`) در همین ترتیب پوشش داده می‌شوند.

## حساب‌ها (سازمان دمو «مجتمع دانش»، slug `danesh-demo`؛ رمز همه بعد از `pnpm seed:demo`: `Demo-1405-pass` — یا مقدار `SEED_DEMO_PASSWORD`)

| نقش | نام | شناسهٴ ورود | کجا |
|---|---|---|---|
| مدیر سازمان | محمد امینی | `09123000001` | لپ‌تاپ |
| مدیر دبیرستان دخترانهٴ دانش (کد `G`) | مریم رضایی | `09123000002` | لپ‌تاپ (بخش مدیریت) |
| دبیر ریاضی ۱۰/۱ و ۱۰/۲ | علی کریمی | `09123000003` | گوشی A |
| دانش‌آموز کلاس ۱۰/۲ | سارا محمدی | `09123000005` | گوشی B |

روی production واقعی به‌جای دمو، همین نقش‌ها با حساب‌های واقعی مدرسه (رمزها از برگه‌ها). **رمز دمو بعد از جلسه تغییر می‌کند** (`SEED_DEMO_PASSWORD` تازه + `pnpm seed:demo` یا «تعیین رمز موقت»).

## وسایل (Props)

- لپ‌تاپ با Chrome، پروژکتور/تلویزیون یا صفحهٴ بزرگ؛ زوم مرورگر ۱۲۵٪.
- **گوشی A** (اندروید، Chrome، اینترنت موبایل — نه وای‌فای مدرسه) — دبیر. **گوشی B** (آیفون Safari یا اندروید دوم) — دانش‌آموز. هر دو با PWA از قبل نصب‌شده و **خارج‌شده** (صفحهٴ ورود).
- برگه‌های چاپیِ اعتبارنامهٴ کلاس ۱۰/۲ (A4، `/admin/classes/<id>/credentials`) در پاکت + یک برگهٴ بریده‌شده برای نشان‌دادن.
- `/roadmap` چاپ‌شده (یک برگ).
- پاکت مهرشدهٴ کلید بازیابی بکاپ (age) — فقط نشان می‌دهید، باز نمی‌کنید.
- ترمینال ssh به سرور از قبل باز و `cd /srv/school`; پنجرهٴ دوم با `pnpm smoke:prod` آماده.
- کاغذ و خودکار برای صورتجلسه؛ چک‌لیست پذیرش چاپ‌شده.

## ۱۰ دقیقه قبل

1. `docker compose ps` سبز، `/api/health` ok، `pnpm smoke:prod` سبز (۷/۷).
2. یک حساب دمو قفل کنید برای بند ۸: ۶ بار رمز غلط برای `09123000004` (زهرا موسوی) یا `update iam.user_account set status='locked' where login_identifier='+989123000004'`.
3. کارتابل سارا را خالی/مرتب کنید (کارهای smoke را بایگانی کنید یا بگذارید — «انجام‌شده»ها بد نیستند).
4. تاریخ فردا را برای مهلت بدانید (جلالی، مثلاً ۱۴۰۵/۰۷/۰۲).
5. صدای اعلان گوشی B روشن.

## سناریو (دقیقه‌ها تقریبی)

**۰:۰۰ — ورود مدیر و خانه (لپ‌تاپ)** — بند ۱، ۳ (بخش مدیر)
- `https://<PUBLIC_HOST>` → قفل مرورگر را نشان دهید («این آدرس فقط با https باز می‌شود»).
- ورود محمد امینی → خانهٴ مدیر: شمارنده‌ها (دانش‌آموز / کارکنان / کلاس / حساب‌های فعال‌نشده)، وضعیت راه‌اندازی، لینک‌های سریع. یک جمله: «هر نقش صفحهٴ خانهٴ خودش را دارد؛ الان دو تای دیگر را می‌بینیم.»

**۱:۳۰ — ساختار مدرسه (`/admin`)** — بند ۷
- «مدیریت» → مدرسه‌ها (دخترانه/پسرانه) → کلاس‌ها → کلاس ۱۰/۲: ۲۱ دانش‌آموز با وضعیت حساب، درس‌ها و دبیران، دکمهٴ «چاپ اعتبارنامه‌ها».
- خروج، ورود **مریم رضایی** (مدیر دبیرستان دخترانه) تا دامنه را نشان دهید: فقط مدرسهٴ خودش را می‌بیند.

**۳:۰۰ — افزودن دانش‌آموز (مدیر خودش کلیک می‌کند)** — بند ۷
- دانش‌آموزان → «دانش‌آموز جدید»: نام، نام خانوادگی، شمارهٴ دانش‌آموزی، موبایل (شمارهٴ خودِ مدیر مدرسه!)، کلاس ۱۰/۲ → ثبت → **رمز اولیه یک‌بار** نمایش داده می‌شود؛ «کپی» کنید. «این رمز هیچ‌جا ذخیرهٴ خواندنی نیست؛ فقط روی برگه.»

**۴:۰۰ — چاپ برگه‌های اعتبارنامه** — بند ۱۰
- کلاس ۱۰/۲ → «چاپ اعتبارنامه‌ها» → پیش‌نمایش چاپ (A4، ۱۲ برگه در صفحه) → پاکت آماده را نشان دهید. «برگه‌ها را می‌برید، می‌دهید، کاغذ اضافه را از بین می‌برید؛ بعد از اولین ورود رمزِ برگه دیگر کار نمی‌کند.»

**۵:۰۰ — دبیر روی گوشی A** — بند ۳، ۵
- ورود علی کریمی → خانهٴ دبیر: «کلاس‌های من» (۱۰/۱، ۱۰/۲ — تعداد دانش‌آموز، کارهای باز)، «کارهایی که دادم» با نوار پیشرفت.
- «کار جدید»: تکلیف، عنوان «حل تمرین‌های صفحهٴ ۴۲»، توضیح یک خط، مهلت فردا ۲۰:۰۰، گیرنده: **کلاس ۱۰/۲** (لیست دانش‌آموزان با تیک؛ می‌توان یکی را برداشت) → ثبت. پیام: «برای ۲۱ نفر ثبت شد».

**۶:۳۰ — دانش‌آموز روی گوشی B** — بند ۲، ۵، ۶
- گوشی B را بالا بگیرید: **نشان (badge)** کارتابل و اعلان بدون لمس بالا می‌رود (≤ ۴۵ ثانیه؛ در این فاصله خانهٴ سارا را توضیح دهید: سلام، کلاس ۱۰/۲، کارت «امروز»، ۵ کار نزدیک).
- اعلان‌ها → «کار جدید به شما سپرده شد» → جزئیات کار → نظر: «تمرین ۳ را متوجه نشدم» → «انجام شد».

**۸:۰۰ — دبیر پیشرفت را می‌بیند (گوشی A)** — بند ۶
- صفحهٴ همان کار: «۱/۲۱ انجام شد»، نظر سارا، اعلان «نظر جدید روی کار». یک جمله دربارهٴ چیزی که **نمی‌شود**: دانش‌آموز فقط کار خودش را می‌بیند؛ کار مدرسهٴ دیگر یا هم‌کلاسی «پیدا نشد» (`docs/qa/security-probe.md`).

**۹:۰۰ — ریست رمز و رفع قفل (لپ‌تاپ)** — بند ۸، ۴
- پروندهٴ زهرا موسوی (قفل‌شده) → «رفع قفل». پروندهٴ سارا → «تعیین رمز موقت» → رمز جدید نمایش → گوشی B همان لحظه به صفحهٴ ورود می‌افتد (نشست باطل) → ورود با رمز موقت → **تغییر رمز اجباری**: رمز «12345678» رد، رمز خوب قبول → خانه.

**۱۰:۳۰ — PWA و خروج امن (گوشی B)** — بند ۱۱
- «بیشتر» → «خروج» → دکمهٴ برگشت/باز کردن دوباره: صفحهٴ ورود، نه کارتابل. آیکون روی هوم‌اسکرین و تمام‌صفحه بودن را نشان دهید (نصب از قبل انجام شده؛ اگر وقت بود مسیر نصب را روی گوشی مدیر تکرار کنید). پیش‌نیاز: بلوک PWA (`manifest`, service worker serwist, CSP) قبل از جلسه deploy شده باشد — چک‌لیست go-live.

**۱۱:۰۰ — بکاپ و بازیابی (ترمینال ssh)** — بند ۱۲
- `ls -la backups/ | tail -3` (فایل `.age` دیشب، `LAST_OK`), `rclone lsf arvan:school-backups/$(hostname)/ | tail -2`, `cat backups/LAST_RESTORE_TEST`. پاکت کلید را نشان دهید: «بدون این کلید، حتی ما نمی‌توانیم فایل را بخوانیم.»

**۱۱:۳۰ — `/roadmap`** و صورتجلسه
- صفحهٴ `/roadmap` (و برگهٴ چاپی): چه چیزی کِی می‌آید — با واژگان خودِ کارفرما (تکالیف، دفتر کلاسی، نمرات و اعتراض، پیام‌ها و کانال کلاس، حساب مالی) و ماهِ تحویل طبق الحاقیه (`docs/client/05-elhaghieh-faz-1.md`). **وضعیت ۱۴۰۵/۰۶/۲۹:** صفحه هنوز placeholder است (بلوک UI/کپی آن را پر می‌کند) — تا آن زمان برگهٴ چاپیِ الحاقیه را نشان دهید. سپس چک‌لیست ۱۲ بند را با مدیر تیک بزنید و صورتجلسه را امضا کنید.

## اگر چیزی خراب شد

| اتفاق | کار |
|---|---|
| badge روی گوشی B بالا نیامد | کشیدن صفحه به پایین (رفرش)؛ توضیح: هر ۴۵ ثانیه از سرور می‌پرسد؛ ادامه دهید |
| اینترنت موبایل ضعیف | هات‌اسپات لپ‌تاپ؛ PWA صفحهٴ «اتصال نیست» را نشان می‌دهد نه دادهٴ قدیمی — این خودش بند ۱۱ است |
| ورود رد شد | حروف انگلیسی/فارسی شماره فرقی ندارد؛ رمز حساس به بزرگی/کوچکی؛ بعد از ۵ خطا ۱۵ دقیقه قفل نرم → حساب دیگر دمو |
| صفحهٴ ۵۰۰ | `docker compose logs --tail=50 app`؛ اگر تازه deploy شده `bash rollback.sh` (۱ دقیقه)؛ وگرنه `docker compose restart app` |
| پروژکتور نمی‌گیرد | همه چیز روی گوشی هم قابل نمایش است؛ بخش مدیریت روی موبایل قابل استفاده است |
