## Layout
`src/app` (routes only; thin) · `src/modules/<ctx>/{schema,dto,repo,service,actions,ui}` for tenancy, iam, config, files, audit, notif, workspace, academic, integ, ops · `src/db/{client.ts,schema/_common.ts}` · `src/lib/{env,logger,normalize,errors,actions,jobs,cn}` · `src/components/ui` (shadcn, generated — do not hand-edit, EXCEPT the two owned files `button.tsx` and `input.tsx` plus our hand-written `select-native.tsx` / `textarea.tsx`: padding-based 44 px controls, see docs/decisions.md «form controls»; a re-generation must re-apply their header blocks) · `scripts/` (migrate, seed, import, worker; tsx) · `drizzle/` (SQL) · `deploy/` (compose, Caddy, ship/deploy scripts) · `tests/{unit,int}`.
Service signature: `(tx, ctx, input)`. Repos take `tx`. Explicit column selects, never `select *`.

## DB rules (non-negotiable)
- The ONLY DB access is `withTenant(ctx, fn)` / `withoutTenant(fn)` from `src/db/client` (ESLint blocks other imports). No raw `db.`; `withoutTenant` only for global tables (organization, user_account, user_session, login_attempt, permission, work_item_status, notification_type) and the read-only `iam.role` / `work_item_type` templates. Every business mutation calls `audit(ctx, action, entity, before, after, tx)` (`src/lib/audit.ts`) in the same transaction. **Never call `set_config(` outside `src/db/client.ts`** (`pnpm verify` greps for it); the login membership lookup uses `tools.bindAccount` from `definePublicAction`.
- Every tenant table has `organization_id` + RLS (ENABLE + FORCE, fail-closed). Composite FKs `(organization_id, x_id)`. Soft delete via `status/archived_at`; `text + CHECK` not pg ENUM; `timestamptz` UTC; UUID v7.
- Migrations: `drizzle-kit generate` → read the SQL → commit → `migrate` service runs it. **Never `drizzle-kit push`; never edit an applied migration; production changes are additive-only** (nullable/DEFAULT columns, expand/contract renames). Every migration ends with `SELECT app.apply_grants();` / `SELECT app.apply_rls();` / `SELECT app.apply_updated_at_triggers();` as separate statements (docs/db.md).
- App connects as `app_rw` (NOSUPERUSER NOBYPASSRLS); migrations as `app_owner` (MIGRATION_DATABASE_URL).

## Action rules
- Every Server Action and Route Handler goes through `defineAction({ schema, permission, scope }, handler)` in `src/lib/actions`. `permission` is REQUIRED (no anonymous actions except login/health — and the pilot-only «ورود آزمایشی» exception below). Order: session → must_change_password → Zod `.strict()` → `can()` → `withTenant` → audit in the same transaction.
- `organization_id`, `person_id`, `created_by` come ONLY from the session — never from input. Never spread client input into `.set()` / `.values()`; map fields explicitly.
- Errors leave the boundary only as `AppError` (`src/lib/errors`) with Persian messages. Proxy is a convenience redirect, NOT a security boundary.
- **Guardians («ولی», docs/decisions.md 2026-10-18):** `guardian_full` is DERIVED from a live `iam.guardian_link` (never granted by hand) and READ-only but for its TWO writes, both in `NON_MANAGER_PERMS` (no manager holds them): `iam.guardian_message.send` («پیام به مدرسه», 2026-10-19: a confidential `parent_message` whose creator — the guardian — is NO participant (`creatorParticipates`); they follow it through `workspace.guardian_message`, never the work item) and `academic.leave.request` («درخواست مرخصی», 2026-10-20, `src/modules/iam/guardian-leave.ts`: ONE child, `requireChild` + the live link locked, the school decides; a guardian cancels only their own pending request); every guardian read and write goes through `requireChild` (`src/modules/iam/guardian-views.ts`) — the live link AND `can(perm, { student })`, never one of them alone; `?child=` is a choice among the caller's own children, never trusted. A guardian never sees the child's personal notes, counseling, other students or admin pages; acting AS a guardian (sheet password, temporary password) needs every child of theirs in the caller's scope.
- **Files («پیوست تکلیف و تحویل پاسخ», owner 2026-10-19, docs/decisions.md):** bytes arrive ONLY through `POST /api/files` (one file, raw body, two defineAction passes — permission + item rule BEFORE a byte is read, then record; same-origin only; excluded from the proxy matcher) and leave ONLY through `GET /files/[id]` (re-authorized on every request, bare 404 otherwise; sniffed Content-Type, nosniff, sandboxed CSP, `attachment` but for images). The kind comes from the BYTES (`src/modules/files/sniff.ts`), never from the client; a client's file name is display text only — never part of a path (`<FILES_DIR>/<org>/<yyyy>/<id>`); audit rows carry ids, sizes and types, never names or content. A write uses only the caller's own `pending` uploads made for it (`takePendingUploads`); removed bytes are deleted after the commit. Limits live in `src/modules/files/limits.ts` only.
- **Background jobs («صف، زمان‌بند و Feature Flag», owner 2026-10-20, docs/decisions.md):** Postgres only — no Redis, no BullMQ. Enqueue with `enqueueJob(tx, ctx, kind, payload, { runAt, dedupeKey })` (`src/modules/ops`) INSIDE the business transaction (outbox); a kind is registered in `src/modules/ops/kinds.ts` (payload `.strict()`, ids and numbers only — never personal text) with its handler in `src/lib/jobs/handlers.ts` (idempotent: delivery is at least once). Handlers run in `withTenant` of the job's organization as the system actor (`SystemCtx`: no person, never passes `can()`; audit rows carry `request_id = job:<id>`, `user_agent = system:worker`) and re-check the domain rule they act on. `src/lib/jobs` (claim, runner, scheduler, worker loop) is importable only from itself, `scripts/` and `tests/` (ESLint); `app.claim_jobs(` only in its runner (`pnpm verify` greps). Recurring work = a `SCHEDULES` entry (`src/modules/ops/schedules.ts`, cron in Asia/Tehran), never a crontab line or a sweep inside a request. Runs in the `worker` compose service (same image, `scripts/worker.mjs`).
- **Feature switches and settings («تنظیمات»):** keys, Persian labels and defaults live ONLY in `src/modules/config/{flags,settings}.ts`; read with `flagEnabled(tx, …)` / `settingOf(tx, …)` in a transaction or `isEnabled(…)` / `getSetting(…)` in pages (school > organization > default); write only through the «تنظیمات» actions (`config.settings.manage`; organization level at the organization, school overrides for overridable keys). A feature not built yet gets its flag `upcoming`, default off. The demo login stays on env, not a flag.
- Auth facts come from `getRequestContext()` (`src/lib/ctx.ts`: cookie → DB session → membership → assignments) — never from proxy headers or the cookie alone. `can(tx, ctx, perm, ref?)` runs inside the action's transaction; login is the only `definePublicAction`. **The ONE other pre-auth entry point (explicit exception, pilot only):** «ورود آزمایشی» — `defineDemoAction` (`src/lib/actions`) for `src/modules/iam/demo-login/actions.ts` (+ its server-side list) and the unlock route `src/app/(auth)/login/demo/route.ts`: NOT_FOUND unless `DEMO_LOGIN=1` AND (a valid `__Host-demo` unlock cookie, minted only for `/login?demo=<DEMO_LOGIN_KEY>` — or the pilot's explicit open mode `DEMO_LOGIN_OPEN=1`, owner 2026-10-18, fake data only), input `{ accountId }` only, and only accounts wholly inside `DEMO_LOGIN_ORGS` (docs/decisions.md 2026-10-18). Never add another public entry point or widen this one; it is switched off before real schools (docs/ops/go-live-checklist.md).

## Frontend rules
- `<html lang="fa" dir="rtl">` is set ONLY in `src/app/layout.tsx`. Never set `dir` elsewhere except `<bdi dir="ltr">` around phone numbers, codes and URLs.
- Tailwind logical utilities only: `ms- me- ps- pe- start- end- text-start text-end rounded-s rounded-e border-s border-e`. NEVER `ml- mr- pl- pr- left- right- text-left text-right`.
- Fonts: `next/font/local` (Vazirmatn variable, `--font-vazir`) only; `next/font/google` is ESLint-blocked. No third-party hosts anywhere (fonts, analytics, CDNs, icons).
- Use `src/lib/cn.ts` for merging classes, never the `cn` package directly (ESLint `no-restricted-imports` blocks `"cn"`/`"cn/*"` everywhere else) — it is configured with our `@theme` roles, so a plain `cn` silently drops `text-row`/`shadow-1`/`rounded-card`/etc.
- **Shell (the hub layout — the only one reachable; a classic bottom-nav/rail path stays in code, behind `getUiVariant()`, for a one-line revert):** no bottom nav, no rail. One sticky top bar on every size. **Home: profile icon (→ «حساب من» at `/more`) at the START, bell at the END. Inner pages: back pill at START, bell + profile at END** (owner 2026-10-06) — the white `TopBarBack` pill (arrow + the parent's name) is drawn by `PageHeader` from its `back` (the ONE source of the target; default «خانه» → `/home`) as a fixed layer over the bar's start slot, and the bar swaps its profile to the end via `:has([data-topbar-back])` — never draw a back link in the page body, never make the bar ask the page. Home = one blue `bg-hero` greeting card, then the role's tiles — every former nav destination («مدرسه(‌ها)», «دانش‌آموزان», «کارکنان», «کلاس‌ها», «نقش‌ها», «برنامهٴ کلاسی», «حضور و غیاب», «پنل من») is a Home tile, never a nav item — then «درس‌های من» course cards (`CourseCover`), then, admins only, a muted «به‌زودی» section. Every inner page's `PageHeader` defaults to «خانه» → `/home` unless it passes an explicit `back`; a `loading.tsx` passes `PageSkeleton` the same `back` when every page under it shares the parent (else a stand-in pill).
- Persian digits via `Intl.NumberFormat("fa-IR")` / `toLocaleString("fa-IR")`; dates via `date-fns-jalali` rendered in `Asia/Tehran`; store UTC.
- All UI text is Persian (نیم‌فاصله where needed); no English strings in UI. Touch targets ≥ 44px. No `dangerouslySetInnerHTML` (ESLint `react/no-danger`).
- **Vocabulary (owner):** class items are «تکلیف» / «تکالیف» in every visible string («تکلیف جدید», «تکالیف داده‌شده», «تکالیف من», «تکالیف نزدیک», «تکالیف این درس»); an admin who does not teach reads the same object as «تسک» and a **student's own** item is «تسک» too («تسک جدید», «تسک‌های من») while a «تکلیف» given TO them keeps its name — the word comes from the ITEM where there is one and from the VIEWER where there is not (`src/lib/work-item-words.ts`: `workItemVoice` vs `createVoice`); a personal `todo` is «یادداشت شخصی» for anyone but a student; «پنل من» is the Home tile / page name (there is no nav — see Shell above); the bell-schedule editor's tile is labelled «برنامهٴ کلاسی» (was «زنگ‌بندی»); teachers are «دبیر» (the seeded role NAME «معلم» stays); «مدرسه» singular for a one-school principal (`schoolsLabelFa`); a parent is «ولی», parents «اولیا» (the student page's «اولیا» card, «ساخت حساب اولیا»), and what a child was given still reads «تکلیف» for them. Routes, permission codes, DB values and type codes are never renamed. Empty states name the context («تکلیفی برای این درس در انتظار نیست»), never «داده‌ای وجود ندارد»; no Latin words in UI.
- **Colour + interaction discipline:** counters are neutral text (a red dot only where the count IS a problem); `success` only for 100 % / completed; yellow only for badges, the one action and high priority; whole-surface links get `surface-link` (hover lift) + an end chevron, static cards never hover; buttons: `default` = the page's one primary action, `outline` = secondary, `ghost` = tertiary (print, mark-all-read); no glow on any CTA; every tappable surface gets a small sink + ink splash on press (`src/lib/tap-ripple.ts`, `TapRipple`, mounted once in the root layout) — no glow, no sound.
- **Admin sections:** `src/lib/admin/nav.ts` is the one list, order «مدرسه‌ها» (org-admin only; its header links to «درس‌ها») · دانش‌آموزان · کارکنان · کلاس‌ها · نقش‌ها; in the (only reachable) hub shell these are Home tiles, not a nav — a school-scoped admin gets «مدرسه» singular instead of the list — and the pill row (`AdminNav`) shows from `lg:` too since there is no rail. The school hub (`/admin/schools/[id]`) lists «کارکنان» / «دانش‌آموزان» rows beside «کلاس‌ها» and a per-school «حضور و غیاب» row (narrowed server-side to that school); `admin-shell.ts` (`getAdminShell`, `adminNavItems`) is the cached scope + counts read. **An organisation admin's context is the ORGANISATION, never a school** (`src/lib/context-place.ts`) — the greeting, «حساب من» and the desktop context bar name the organisation even in a single-school org. Resource lists: `PageHeader` with count + primary action, phone card rows from `mobileMeta` columns, the «⋯» `RowActions` menu on desktop.
- Tokens live in `src/app/globals.css` (`@theme`: primary 50–900 persian-blue `#072AC8`, `sky`/`sky-strong` accent (icons, fills, links — never small sky text on white), `info`/`info-soft` soft surfaces, `warning` yellow = FILL only with navy text (`warning-text` for text), success/danger, navy-tinted neutrals; `canvas` `#E8EEF9` is the page ground under the shell (white cards lift off it) — the auth pages (/login, /change-password) are instead the fixed dark door «درِ تیره» (owner 2026-10-18: `.auth-night`-scoped palette, glass card, `DoninoMark3D`; never reuse it inside the app), `surface-sunken` the lighter tint INSIDE cards (row hover, inputs); radius 12px controls / 16px cards (`rounded-card`) / 20px hero (`rounded-hero`); shadow `shadow-1` (cards); gradients: `bg-hero` and the `.clay-icon` material only; `--color-cover-{0..7}-{light,base,dark,ink}` is a SEPARATE, vivid 8-set palette for «درس‌های من» course covers (`CourseCover`) only — stamps, `SubjectIcon` and timetable cells stay on the muted subject hues, never the cover tokens).
- **Type scale** (`text-*` roles, never ad-hoc sizes): `text-display` 28/34 (desktop page titles), `text-title` 24/32 (phone page titles, dashboard numbers), `text-section` 18/28 (section headings), `text-row` 15/24 (row titles, table cells), body `text-sm` 14/24 (the `body` default), `text-meta` 13/20 (meta lines, hints, table headers), `text-cell` 11 px semibold (the phone timetable's weekday header letters only). `text-xs` 12 px is for pills/badges ONLY.
- **Surface roles** (utilities in `globals.css`): `surface-work` = white + `shadow-1`, the page's primary content (ONE per view, not a stack; «پنل من» and the subject page show their تکالیف as ONE `WorkItemList` box — open rows, then «انجام‌شده‌ها», a status tag per row — no tabs, no bucket boxes); `surface-panel` = `surface-sunken` tint + hairline, no shadow — supporting panels, asides, stat rows, the circle behind a row glyph; `surface-quiet` = no box, heading + hairline under the section. `surface-link` (+ `pressable`) = a whole-surface link: hover lift + end chevron; static cards never hover. Never `rounded-card bg-surface shadow-1` by hand.
- **Layout primitives** (`src/components/layout`): every page = `ContentWidth` (1200 px, `size="reading"` 48 rem for detail/forms) → `PageHeader` (title, description, `count`, `back`, `actions`; from `lg:` it also draws the slim context bar «مدرسه · سال · نوبت · date» from `getShellContext()`) → `PageSection` (`surface="work" | "panel" | "quiet"`) and, on dashboards/details, `TwoColumn` (`lg:grid-cols-12`, main 8/7 + aside 4/5). No ad-hoc `px-4 pt-… flex-col` page wrappers, no bespoke title rows (`AdminHeader` is an alias of `PageHeader`). Icons (Design v2 restraint): the clay mark (`ClayIcon`, `src/components/ClayIcon.tsx` — the calm persian-blue squircle, ONE blue for every live mark, `yellow` only for the one action «تکلیف جدید» / high priority, `grey` for «به‌زودی») lives ONLY on the Home tiles, the nav's «خانه» mark, illustration/empty-state spots and login. A row (or the subject page header) that belongs to a درس leads with `SubjectStamp` («مُهر درس», `src/components/SubjectStamp.tsx`: the درس's first letters on one of eight muted subject hues — data colour, docs/decisions.md). The hue is the درس's (`subjectHue`) for students and admins; for a TEACHER's own classes it is per class offering (`teacherOfferingHues` → `hue` prop / `offeringHue`; `getTeacherHues()` per request), so each of a دبیر's classes has one colour on the course cover, timetable cells, marks and rows — the eight hues only, never a new one. A subject LIST row or header whose title IS the درس name («درس‌ها و دبیران», «درس‌های من», the subject page header, the timetable details card, today's attendance rows) uses `SubjectIcon` instead («نشان درس», same file: the درس's own lucide glyph from `src/lib/subject-icon.ts` on the same hue), so no subject list repeats one grey mark. Every other list row, notification, «بیشتر» row, admin row, detail fact and timetable cell uses `RowMark` (`src/components/RowMark.tsx`: a 20 px lucide glyph, `text-muted`, in a 32 px `surface-panel` circle — or `bare`); priority is `PriorityDot` beside the title (yellow high, red urgent), never the mark. No new hue, no glow, no bare icon as a row mark. Illustrations: `src/components/illustrations` (inline SVG, no assets).

## Workflow
- `pnpm verify` (typecheck + lint + unit tests) must pass before every commit; `pnpm build` before every deploy. Int tests: `pnpm test:int` (needs Docker Postgres).
- Deploy = `deploy/ship.ps1` (build on Windows → `docker save | ssh docker load` → `deploy.sh`). Never build on the VPS.
- Edit files with the Edit tool, Python or Git Bash `sed` — never `Get-Content | Set-Content` in PowerShell 5.1 (it re-encodes UTF-8 through the ANSI codepage and destroys Persian text).
- **45-minute rule:** a bug not fixed in 45 min → revert to the last green commit and ask for a simpler approach. Commit after every vertical slice.
